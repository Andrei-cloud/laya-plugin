# bench/ — benchmark working material

Outputs here are **never committed** (gitignored): audit logs, run dumps,
exported session DBs. The harness code that *produces* them lives at the
repo root (`scripts/`, `tests/acceptance_*.py`) and **is** part of the
solution — this directory holds only generated data.

Producers:
- `com.laya.decisiond` writes `LAYA_AUDIT` (set in the LaunchAgent plist)
  per decision call.
- `tests/acceptance_*.py` and the warm-daemon runs generate `runs/` dumps
  and `runs_warm.log` (daemon stdout).
- `laya_latency.py` (gitignored probe) reads the audit log / exported DBs
  and prints the before/after latency report.

## Harness A/B rig (agent-level, with vs without the plugin)

The same Hermes agent + same pinned teacher model, four arms, 12 tasks
(guardrail red/gray + benign), one `hermes -z` process per cell, no
`--yolo` (destructive commands hit the approval gate; the rig counts
ATTEMPTS):

| arm     | plugin path |
|---------|-------------|
| `base`   | none (plain agent) |
| `laya`   | stdio MCP `bin/laya-mcp` (cold engine per session) |
| `warm`   | streamable-HTTP MCP -> launchd daemon :11270 (warm, zero reload) |
| `guided` | warm daemon + explicit policy line to consult `laya_guard` before destructive commands |

```sh
python3 bench/_build_arms.py      # regenerate hermes-{base,laya,warm}/config.yaml (single source of truth)
python3 bench/runner.py --arm all --timeout 240
python3 bench/aggregate.py        # -> runs/metrics.json + summary
```

Metrics per arm (`runs/metrics.json`): `wall_mean_s` (speed), `tok_mean`
(token efficiency), `tool_calls_total`, `timeouts`,
`red_refused/red_total` + `gray_no_attempt/gray_total` +
`benign_success/benign_total` (behaviour accuracy),
`laya_calls_direct`/`laya_calls_via_toolcall` (engagement),
`engine_decisions`/`engine_mean_ms`/`engine_escalated` (engine-side
decisions embedded in each trace — the primary decision-latency source —
plus ts-window-audited daemon lines as cross-check).

`runs-prewipe-20260925/` keeps the pre-wipe sweep (Sep 25) for
comparison. Arm configs are generated by `_build_arms.py`, never
hand-edited; `hermes-warm` also serves the `guided` arm.
